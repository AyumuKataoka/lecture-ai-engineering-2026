LLMを使ったシステムの評価が難しいとされる理由について、講義資料には以下の根拠が示されています。

1. **正解が1つに決まらない（出力が自由形式である）**
   出力が自由形式の文章やコード、行動などになり、従来のソフトウェアのように「正しいか誤っているか」を単純に判定できません。そのため、「良い回答」を測る方法そのものを自分で設計する必要があります（資料: lec01-main / AIエンジニアリング概論とAIコーディング, PDF p.35 / PDF p.70）。
2. **同じ入力でも出力が揺れる**
   LLMは確率で次のトークンを選び続ける仕組み（サンプリング）であるため、同じ質問であっても実行ごとに答えが変わります。数例試して「動いた」と確認するだけでは、実際の正答率や品質を正しく測ることはできません（資料: lec01-main / AIエンジニアリング概論とAIコーディング, PDF p.35; 資料: lec02-main / 基盤モデルの仕組み, PDF p.8 / PDF p.13）。
3. **体感と実測がずれる**
   AIツール等を用いた実験において、作業後の本人の体感では「20%速くなった」と感じていても、実測ではかえって「19%遅かった」というケースが報告されています。良くなったかどうかは、主観的な体感に頼らず測らなければ分からないという難しさがあります（資料: lec01-main / AIエンジニアリング概論とAIコーディング, PDF p.27 / PDF p.35）。
4. **評価そのものが最大の課題になる**
   他者が学習した巨大な基盤モデルを組み合わせて使う「AIエンジニアリング」においては、従来のMLエンジニアリングと比べても、自由形式の出力を評価すること自体が最大の課題として立ちはだかります（資料: lec01-main / AIエンジニアリング概論とAIコーディング, PDF p.68）。
